## 🎯 Project Introduction

**OneClickSuite** is an **AI-powered product image generation platform** designed for e-commerce sellers. Upload a single product photo, and AI automatically generates a complete product image library, supporting major e-commerce platforms like Amazon, TEMU, Shopify, and TikTok Shop.

> 🚀 **No design skills required. Zero learning curve. No studio needed. Save 90% on costs.**

## 🚀 Quick Start

### Environment Requirements

| Dependency       | Version      |
| :------------ | :------- |
| Node.js          | >= 18.x |
| npm              | >= 9.x  |
| Vercel CLI       | Latest version |

### Installation Steps

```bash
# 1. Clone the repository
git clone https://github.com/YuanCheng888/OneClickSuite.git
cd OneClickSuite

# 2. Install dependencies
npm install

# 3. Configure environment variables
cp .env.example .env

# 4. Start development server
vercel dev

# 5. Access the application
# Open http://localhost:3000
```

### Environment Variables Configuration

Edit `.env` file and configure the following key parameters:

```env
# Application Configuration
VITE_APP_NAME=OneClickSuite

# Supabase Database Configuration (Required)
VITE_SUPABASE_URL=your_supabase_url
VITE_SUPABASE_ANON_KEY=your_supabase_anon_key
SUPABASE_SERVICE_ROLE_KEY=your_supabase_service_role_key

# AI Service Configuration (Required)
GEMINI_API_KEY=your_gemini_api_key
GEMINI_BASE_URL=https://generativelanguage.googleapis.com/v1beta

# Payment System Configuration (Choose one)
# Option 1: Use Creem (Recommended)
CREEM_API_KEY=your_creem_api_key
CREEM_WEBHOOK_SECRET=your_creem_webhook_secret
VITE_CREEM_PUBLISHABLE_KEY=your_creem_publishable_key

# Option 2: Use Stripe
STRIPE_SECRET_KEY=your_stripe_secret_key
STRIPE_WEBHOOK_SECRET=your_stripe_webhook_secret
VITE_STRIPE_PUBLISHABLE_KEY=your_stripe_publishable_key
```

### Stripe Configuration Instructions

To use Stripe payment system, ensure the following configuration:

1. **Create Stripe Account**: Visit [Stripe Dashboard](https://dashboard.stripe.com/) to register
2. **Get API Keys**:
   - `STRIPE_SECRET_KEY`: Get from Stripe Dashboard
   - `STRIPE_WEBHOOK_SECRET`: Generate via `stripe listen --forward-to localhost:3000/api/webhook/stripe`
   - `VITE_STRIPE_PUBLISHABLE_KEY`: Get from Stripe Dashboard
3. **Configure Webhook**: Configure the following events in Stripe Dashboard:
   - `checkout.session.completed`
   - `customer.subscription.created`
   - `customer.subscription.updated`
   - `customer.subscription.deleted`

### Deploy to Production

```bash
# Build production version
npm run build

# Deploy to Vercel
vercel deploy --prod
```

## 📖 Usage Flow

```
Upload → AI Analysis → Blueprint → Rendering → Complete
```

1. **Login/Register** - Use email verification code to log in

4. **Blueprint** - AI generates complete creative planning scheme
5. **Rendering** - After confirming the plan, AI batch generates high-quality product images
6. **Complete** - View, edit, and download generated images in Creative Gallery

## 🗄️ Supabase Database Schema

### 📊 Core Business Tables

| Table | Description | Key Fields |
| :--- | :--- | :--- |
| `profiles` | User center: credits balance, subscription tier, payment platform links, UI language | credits, tier, stripe_customer_id, creem_customer_id, app_language |
| `generations` | AI task records: analyze/generate/edit types, complete lifecycle tracking | type, status, prompt(jsonb), full_prompt(jsonb), result(jsonb) |
| `assets` | File assets: product images, masks, generated images storage paths and metadata | storage_path, public_url, asset_type, generation_id |
| `credit_rules` | **Dynamic credit rules**: admin-configurable credit cost per operation | action_type, cost, description |
| `credit_logs` | **Complete audit trail**: every credit change is logged for traceability | user_id, action_type, change_amount, balance_after, metadata(jsonb) |
| `credit_packages` | Credit package definitions: name, credit quantity, price, tier, payment product ID | credits, price, tier, creem_product_id |
| `orders` | **Payment order records**: platform, order number, amount, full lifecycle status | provider, provider_order_id, amount, status, metadata(jsonb) |
| `transaction_logs` | **Transaction debug logs**: intermediate state records for atomic operations | user_id, action, status, details(jsonb) |
| `mode_models` | **AI model configuration**: models used for different modes and priority | mode, model_name, priority |

### 🤖 AI Model Configuration Table `mode_models`

**Important: All AI model configurations are dynamically read from Supabase, supporting runtime switching without code changes.**

| Field | Type | Description |
| :--- | :--- | :--- |
| `mode` | text | Operation mode: `analyze` / `generate` / `edit` |
| `model_name` | text | AI model name (e.g., `gemini-3.1-flash-image-preview`) |
| `priority` | smallint | Priority (1=highest, supports model fallback) |

**Usage Scenarios**:
| Mode | Purpose | Example Models |
| :--- | :--- | :--- |
| `analyze` | AI analysis phase after product image upload | gemini-2.5-pro (primary), gemini-3-pro-image-preview (fallback) |
| `generate` | Batch product image generation phase | gemini-3.1-flash-image-preview (primary), gemini-3-pro-image-preview (fallback) |
| `edit` | Single image local redraw/optimization phase | gemini-3.1-flash-image-preview (primary), gemini-3-pro-image-preview (fallback) |

### 💰 Credit System

#### Credit Rules Table `credit_rules` (Dynamically Configurable)
| action_type | Default Cost | Description |
| :--- | :---: | :--- |
| `analyze` | 5 credits | Product analysis |
| `generate` | 5 credits/image | Image generation |
| `edit` | 5 credits/session | Image editing |
| `new_user_bonus` | 25 credits | New user registration bonus |

> 🔧 **Admins can modify credit rules directly in Supabase Dashboard, effective immediately without code changes.**

#### Credit Logs Table `credit_logs` (Complete Audit)
| Field | Description |
| :--- | :--- |
| user_id | User identifier |
| action_type | Operation type |
| change_amount | Change amount (positive/negative) |
| balance_after | Balance after change |
| metadata | Extended info (JSON): task ID, generation count, failure reason, etc. |
| created_at | Timestamp |

### 🛒 Payment System

#### Orders Table `orders` Complete Fields
- `provider`: Payment platform (creem/stripe)
- `provider_order_id`: Platform order number (globally unique)
- `package_id`: Package ID
- `external_product_id`: External product ID
- `amount`: Amount
- `currency`: Currency type
- `status`: Order status (pending/paid)
- `metadata`: Extended info (JSON)

#### Transaction Logs Table `transaction_logs`
Used for debugging payment atomic operations, recording state changes at each step.

### 📁 File Storage

| Bucket | Type | Purpose | Lifecycle | Access Control |
| :--- | :--- | :--- | :--- | :--- |
| `generated-images` | Private | User-generated AI images | Permanent | User can only access `{user_id}/*` |
| `temp-uploads` | Private | Temporary upload files | **Auto-cleanup after 24h** | User can only access `{user_id}/*` |

### ⚡ Stored Procedures (RPC Functions)

| Function | Input Parameters | Return Value | Permission | Purpose |
| :--- | :--- | :--- | :--- | :--- |
| `consume_credits` | user_id, action_type, metadata | {success, remaining_credits} | **Service Role Only** | Atomic credit deduction |
| `add_credits` | user_id, amount, reason, metadata | {success, new_balance} | **Service Role Only** | Atomic credit addition |
| `process_creem_payment` | Payment callback params | Complete processing result | **Service Role Only** | Creem payment atomic processing: create order + add credits + update subscription |
| `process_creem_cancellation` | customer_id, subscription_id | Processing result | **Service Role Only** | Subscription cancellation/expiration handling |
| `cleanup_temp_uploads` | - | Cleanup count | **Service Role / Cron** | Cleanup files older than 24h |

### 🔔 Automatic Triggers

#### `handle_new_user` - New User Registration Auto-Processing
```sql
Trigger: auth.users inserts new user
Auto-execute:
  1. Read new_user_bonus credit amount from credit_rules
  2. Create user profile (with initial credits)
  3. Record credit_logs new user bonus log
```
> ⚡ **The entire registration process is automated, no backend involvement required.**

#### `consume_credits` - Atomic Credit Deduction
```sql
Execution flow:
  1. Query credit_rules to get current credit cost
  2. FOR UPDATE lock user credit record (prevent concurrency)
  3. Check if balance is sufficient
  4. Deduct credits and update profiles
  5. Record credit_logs complete log
  6. Return processing result
```
> 🔒 **Atomicity guaranteed: balance check → deduction → logging completed in the same transaction.**

### 🛡️ Row Level Security (RLS)

| Table | Read Policy | Write Policy |
| :--- | :--- | :--- |
| profiles | Users can only read their own data | Can only modify basic info, credits/tier controlled by Service Role |
| credit_rules | **Public read** (all users can view credit rules) | Only Service Role can modify |
| credit_logs | Users can only read their own logs | Only Service Role can write |
| generations | Users can only operate their own tasks | Only Service Role can create |
| assets | Users can only operate their own files | Same as above |
| mode_models | **Public read** (frontend needs to get model config) | Only Service Role can modify |
| orders | Users can only read their own orders | Only Service Role can create/modify |
